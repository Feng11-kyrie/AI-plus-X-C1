# 拿来说明（3 篇）

挑战要求：**至少 3 个「拿来说明」——某个关键决策/产出是怎么借助 AI 做出来的（含原文、prompt、产出、对比）。**

下面每一篇都按 **原文 → prompt → 产出 → 对比** 四段组织，末尾附可核对的文件位置。
所有数据都来自本仓库的 `git` 历史与 `logs/journal.jsonl`，可逐条复核。

| # | 篇目 | 一句话 |
|---|---|---|
| 01 | [清洗管线为什么静默丢掉了 9,156 字符正文](01-清洗管线静默丢内容.md) | 我断言「清洗质量很高」，实际有 4 个静默丢内容的 bug；转折点是意识到**管线里没有任何机制能替我发现自己看漏了** |
| 02 | [术语校验器的 17 次拦截，其中 6 次才是我真错了](02-术语校验器的十七次拦截.md) | 术语表写进了 prompt，36 块里仍违反 17 次；而分析后发现**机器判错的次数比我还多** |
| 03 | [把「覆盖 80%」从一个说法变成可核对的数字](03-覆盖度分母的定义.md) | 分母没人定义过；而它决定了只翻 HTML 是 **76.5%**（不达标）、纳入 PDF 才是 **85.3%** |

## 三篇的共同主线

如果把三篇压缩成一句话：

> **约定写进 prompt 只是请求，写成代码才是约束；
> 但代码也会错，所以人必须保留"判断规则对不对"的权力。**

三篇分别从三个角度印证这条：

- **01** —— 「输出看起来对吗」是抽样式信任（样本量为 1 时几乎必然漏检）；
  「原文里有多少、输出里还剩多少」是穷举式信任，差值自动暴露问题。
- **02** —— 17 次拦截里只有 6 次是真违规。若盲信工具，
  我会把「模型上下文协议（MCP）」改坏、把正确的「威胁建模」改错。
- **03** —— 分母不是统计口径问题，而是任务边界问题。
  定义不清会导致"翻了 26 篇才发现不达标"。

## 一条贯穿的方法

三篇里反复出现的同一个动作：**换个提问方向**。

| 原来的问法 | 换成的问法 | 结果 |
|---|---|---|
| 清洗输出看起来对吗？ | 原文里有多少元素，输出里还剩多少？ | 抓出 4 个静默丢内容 bug |
| 译文符合术语表吗？ | **规则本身对不对？** | 发现 11/17 次拦截是规则的问题 |
| 有多少条 readings？ | 哪些真有本地文件？文件里真有内容吗？ | 分母从 44 收敛到 34，发现 3 个隐形缺口 |

**同一个项目、同一批数据，只是换了提问方向，问题就从"看不见"变成"自己跳出来"。**
