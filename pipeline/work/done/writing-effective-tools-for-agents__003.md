### 运行评估

接下来，你需要通过运行评估来衡量 Claude 使用你工具的表现。先从生成大量植根于真实用途的评估任务开始。我们建议与智能体协作，帮你分析结果并确定如何改进工具。完整流程可参见我们的[工具评估 cookbook](https://platform.claude.com/cookbook/tool-evaluation-tool-evaluation)。

*我们内部 Slack 工具在留出测试集上的表现*

**生成评估任务**

有了早期原型，Claude Code 可以快速探索你的工具，并创建几十组提示词与响应对。提示词应当源自真实用途，并基于真实的数据源与服务（例如内部知识库与微服务）。我们建议避免那种过于简单、流于表面的「沙箱」环境——它们无法用足够的复杂度去压测你的工具。好的评估任务可能需要多次工具调用——甚至几十次。

以下是一些**好的**任务示例：

- 下周与 Jane 安排一次会议，讨论我们最新的 Acme Corp 项目。附上上次项目规划会议的记录，并预订一间会议室。
- 客户 ID 9182 反映，一次购买尝试被扣了三次款。找出所有相关日志条目，并判断是否有其他客户受同一问题影响。
- 客户 Sarah Chen 刚刚提交了取消申请。准备一份挽留方案。要确定：(1) 他们为什么离开，(2) 什么样的挽留方案最有吸引力，(3) 在提出方案之前我们应当注意哪些风险因素。

以下是一些**较弱的**任务示例：

- 下周与 jane@acme.corp 安排一次会议。
- 在支付日志中搜索 purchase_complete 和 customer_id=9182。
- 找出客户 ID 45892 提交的取消申请。

每个评估提示词都应配一个可验证的响应或结果。你的验证器可以简单到把标准答案与采样响应做精确字符串比较，也可以复杂到请 Claude 来评判响应。避免使用过于严苛的验证器——它们会因为格式、标点或合理的替代表述这类无关差异，而否掉正确的响应。

对于每组提示词—响应对，你还可以选择性地指定预期智能体在解决该任务时应调用的工具，以便在评估中衡量智能体是否成功把握了每个工具的用途。不过，由于正确解决任务可能存在多条有效路径，请尽量避免把策略规定得过死或过拟合。

**运行评估**

我们建议用直接调用 LLM API 的方式以程序化方式运行评估。使用简单的智能体循环（用 `while` 循环包裹交替进行的 LLM API 调用与工具调用）：每个评估任务一个循环。每个评估智能体应被给予单个任务提示词与你的工具集。

在评估智能体的系统提示词中，我们建议指示智能体不仅输出结构化响应块（用于验证），还要输出推理与反馈块。指示智能体把这些内容放在工具调用与响应块**之前**输出，可能通过触发思维链（CoT）行为来提升 LLM 的有效智力。

如果你用 Claude 运行评估，可以直接开启[交错思考](https://docs.anthropic.com/en/docs/build-with-claude/extended-thinking#interleaved-thinking)来「开箱」获得类似能力。这有助于探查智能体为什么调用或不调用某些工具，并凸显工具描述与规格说明中具体的改进点。

除顶层准确率外，我们建议收集其它指标，例如单次工具调用与任务的总运行时长、工具调用总次数、Token 总消耗量，以及工具错误数。跟踪工具调用有助于揭示智能体常走的共性工作流，也为工具合并提供了一些机会。
