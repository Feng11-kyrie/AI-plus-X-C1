## 风格问题

大括号位置、变量／函数命名、缩进与空格问题应当处理，但它们**不是**好的代码评审的核心目的（注意我把它们放在了代码评审金字塔的最顶端）。如果你发现团队 90% 的时间都花在纠结缩进和变量名上，那你大概在把大家的时间浪费在本来大部分可以自动化的事情上。写一份风格指南，在提交时强制检查缩进与空格，然后把时间花在价值更高的问题上。我并不是要贬低一致风格的重要性。恰恰相反，拥有一致且符合惯例的风格，是让代码库易读易懂最简单的方式之一。但如果你所有的代码评审都聚焦在这些简单琐碎的任务上，就该问问自己：你是不是在回避那些更难、也更重要的工作——让团队在认知上保持对齐，并思考更高层面的设计。
