## 面向强化学习工程的 Claude Code

**对开发工作流的影响**

**实验性做法成为可能**
他们现在采用「试了不行就回滚」的方法，频繁提交检查点，从而能测试 Claude 的自主实现尝试并在需要时回退，让实验做得更多。

**文档加速**
Claude Code 会自动加上有用的注释，在文档上省下大量时间——不过他们也指出，它有时会把注释加在奇怪的位置，或采用可疑的代码组织方式。

**提速但有局限**
Claude Code 能在他们「花相对很少时间」的情况下实现中小型 PR，但他们也承认，它只有大约**三分之一**的情况能一次成功，其余需要额外引导或人工介入。

**强化学习工程团队的头号建议**

**为特定模式定制你的 Claude.md 文件**
在 Claude.md 文件里加指令，防止 Claude 反复犯工具调用方面的错误，例如告诉它「用 pytest 而不是 run，不要不必要地 cd——直接用正确路径就行」。这显著提升了稳定性。

**采用重视检查点的工作流**
Claude 做改动时，你要定期提交，这样实验失败时能轻松回滚。这让开发方式更具实验性而没有风险。

**先试一次性方案，再转向协作**
先给 Claude 一个简短的提示词，让它尝试完整实现。如果成了（大约三分之一的情况），你就省下了大量时间；如果没成，再切换到更具协作性、有引导的方式。

## 面向法务的 Claude Code

法务团队是通过实验、以及想了解 Anthropic 产品能力的愿望，发现了 Claude Code 的潜力。此外，有一位团队成员有一个与为家人和工作创建无障碍工具有关的个人用例，由此产出的原型向非开发者展示了这项技术的力量。

**Claude Code 的主要用例**

**为家人定制的无障碍方案**
团队成员为因医学诊断而存在言语困难的家庭成员构建了沟通助手。他们只用一小时就做出了一个预测输入应用：使用原生语音转文字，给出建议回复、并用语音库朗读出来，填补了言语治疗师推荐的现有无障碍工具的空白。

**法务部门工作流自动化**
他们做了「电话树」系统原型，帮助团队成员联系到 Anthropic 内部合适的律师，展示了法务部门如何在无需传统开发资源的情况下，为常见任务构建定制工具。

**团队协作工具**
管理者们构建了 G Suite 应用，自动完成每周团队更新，并跟踪各产品的法务评审状态，让律师只需点几下按钮就能标出需要评审的条目，而不必维护表格。

**快速原型以验证方案**
他们用 Claude Code 快速构建可用的原型，拿去给领域专家看（例如把无障碍工具展示给 UCSF 的专家），从而在投入更多时间之前验证想法、并找出已有的解决方案。
