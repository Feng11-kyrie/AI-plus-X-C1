## 面向产品开发的 Claude Code

**团队成效**

**功能实现更快**
成功实现了 Vim 模式这类复杂功能，其中 70% 的代码由 Claude 自主编写。

**开发速度提升**
能快速做功能原型、迭代想法，而不被实现细节拖住。

**通过自动化测试提升代码质量**
Claude 生成全面的测试并处理例行的 bug 修复，在减少人工投入的同时维持高标准。

**更好的代码库探索**
团队成员无需等待同事回复，就能快速理解 monorepo 中不熟悉的部分。

**Claude Code 团队的头号建议**

**搭建自给自足的循环**
把 Claude 设置为能自行验证工作：自动运行构建、测试与代码检查。这让 Claude 能更长时间自主工作并抓住自己的错误，在你要求它在写代码之前先生成测试时尤其有效。

**培养任务分类的直觉**
学会区分哪些任务适合异步处理（外围功能、做原型），哪些需要同步监督（核心业务逻辑、关键修复）。产品边缘的抽象任务可以用「自动接受模式」处理，而核心功能需要更密切的看护。

**写出清晰、详细的提示词**
当组件名称或功能相近时，你的请求要极其具体。提示词写得越好、越详细，你就越能信任 Claude 独立工作，而不会意外改到代码库里错误的部位。

## 面向安全工程的 Claude Code

安全工程团队专注于保障软件开发生命周期的安全、供应链安全与开发环境安全。他们大量使用 Claude Code 来编写和调试代码。

**Claude Code 的主要用例**

**复杂基础设施调试**
处理故障事件时，他们把调用栈与文档喂给 Claude Code，让它沿代码库追踪控制流。这显著缩短了生产问题的解决时间——原本需要 10–15 分钟人工扫代码才能理解的问题，现在大约 5 分钟就能搞定。

**Terraform 代码评审与分析**
对于需要安全审批的基础设施变更，他们把 Terraform plan 复制进 Claude Code，问「这会产生什么效果？我会不会后悔？」这形成了更紧的反馈回路，让安全团队能更快评审并批准基础设施变更，减少开发流程中的阻塞。

**文档整合与运维手册**
他们让 Claude Code 摄取多个文档来源，产出 markdown 格式的运维手册、排障指南与总览。他们把这些浓缩后的文档作为调试真实问题的上下文，比在完整知识库里翻找更高效。

**测试驱动开发工作流**
他们不再沿用过去「设计文档 → 潦草代码 → 重构 → 放弃测试」的模式，而是让 Claude Code 先给出伪代码，引导它走测试驱动开发，并定期检查、在卡住时给它纠偏，从而得到更可靠、更可测的代码。

**上下文切换与项目上手**
在为既有项目（例如用于安全审批工作流的 Web 应用 dependant）做贡献时，他们会用 Claude Code 编写、评审并执行以 markdown 写在代码库中的规格说明，从而在**几天**而非**几周**内做出有意义的贡献。
