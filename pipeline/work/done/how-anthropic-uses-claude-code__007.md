## 面向增长营销的 Claude Code

**团队成效**

**重复性任务大幅省时**
广告文案创作从 2 小时缩短到 15 分钟，腾出时间做策略性工作。

**创意产出提升 10 倍**
借助自动生成与 Figma 集成，团队现在能在各渠道测试多得多的广告变体。

**像更大的团队一样运作**
团队能承接那些传统上需要专职工程资源的任务。

**重心转向策略**
团队能把更多时间花在整体策略与构建智能体自动化上，而不是手工执行。

**增长营销团队的头号建议**

**找出有 API 的重复性任务**
寻找那些重复性动作、且所用工具（例如广告平台、设计工具、分析平台）提供 API 的工作流。它们是最适合自动化的对象，也是 Claude Code 价值最大的地方。

**把复杂工作流拆成专职子智能体**
不要试图用一个提示词或一套工作流处理一切，而是为特定任务建立各自独立的智能体（如同他们的标题智能体与描述智能体）。面对复杂需求时，这让调试更容易、输出质量也更高。

**编码之前先充分头脑风暴并规划提示词**
先花足够时间用 Claude.ai 把整个工作流想透，再让 Claude.ai 产出一份完整的提示词与代码结构，供 Claude Code 参照。此外，要一步一步来，而不是直接要一次性方案，以免 Claude 被复杂任务压垮。

## 面向产品设计的 Claude Code

产品设计团队为 Claude Code、Claude.ai 与 Anthropic API 提供支持，专长是构建 AI 产品。即便是非开发者，也能用 Claude Code 弥合设计与工程之间传统的鸿沟，把自己的设计构想直接实现出来，而不必与工程师反复来回。

**Claude Code 的主要用例**

**前端打磨与状态管理改动**
他们不再为字体、颜色、间距这类视觉微调写大量设计文档、并与工程师来回反馈多轮，而是直接用 Claude Code 实现这些改动。工程师们注意到，他们在做着「通常不会看到设计师去动的大规模状态管理改动」，从而实现了他们心中所想的精确质量。

**用 GitHub Actions 自动开工单**
借助 Claude Code 的 GitHub 集成，他们只需提交描述所需改动的 issue／工单，Claude 就会自动提出代码方案，甚至不必打开 Claude Code，为那堆积压已久的打磨类任务形成了一条无缝的修 bug 与功能精修工作流。

**快速交互式原型**
把设计稿图片粘贴进 Claude Code，他们就能生成功能完整、工程师能立刻看懂并继续迭代的原型，取代了过去「静态 Figma 设计稿 + 大量解释 + 翻译成可运行代码」的传统循环。

**发现边界情况与理解系统架构**
他们用 Claude Code 梳理错误状态、逻辑流与系统的各种状态，从而能在**设计阶段**就发现边界情况，而不是等到开发时才撞见，从根本上升级了初始设计的质量。

**复杂文案改动与法律合规**
对于诸如在整个代码库里移除「研究预览」字样这类任务，他们用 Claude Code 找出所有出现位置、审阅周边文案、与法务实时协调改动并实施更新——这个过程只用了两通 30 分钟的电话，而不是一周的来回协调。
