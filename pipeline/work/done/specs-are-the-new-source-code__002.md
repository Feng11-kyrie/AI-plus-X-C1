## 等等，原型不是已经把规格文档干掉了吗？

直到最近，产品生命周期都不得不从规格文档（或 PRD、概念文档、餐巾纸）开始，由它来启动最初的线框图、设计、原型与最小可行产品（MVP）开发。

传统做法让人觉得是不得不忍受的恶。工程师构建基础的 MVP，只为把某样东西——任何东西——送到客户手里。「如果你对产品的第一版不感到难堪，说明你发布得太晚了」成了信条。

我们构建产品的整套方法近来发生了重大转变，在这个新世界里，**规格文档往往是产出，而不是输入**。

今天，你不需要发布一行代码就能把原型送到客户手里。v0、Lovable、Replit 这类工具让你在几小时内——而不是几周内——搭出能跑的原型，而且不需要工程投入。

这不只是更快——而是根本不同。手里有了一个「氛围编程」出来的原型，你可以在写下一行功能规格之前就收集真实客户反馈。你可以验证假设、迭代流程、打磨交互。

- **旧的工作流是这样的**：模糊的想法 → 线框图 → 设计 → 由工程师构建的 MVP → 客户反馈 → 痛苦的规格修订 → 线框图 → 设计 → 重做 → 祈祷。
- **新的工作流**：模糊的想法 → 快速原型 → 客户反馈 → 清晰到不能再清晰的规格 → AI 辅助实现。

原型没有把规格文档干掉。它们让规格文档变得更好。
