## 面向产品设计的 Claude Code

**团队成效**

**核心工作流被改造**
Claude Code 成为主要设计工具，Figma 与 Claude Code 有 **80%** 的时间同时开着。

**执行速度快 2–3 倍**
过去需要与工程师大量来回的视觉与状态管理改动，现在直接实现。

**周期从数周缩到数小时**
像 GA 发布文案这种原本要一周协调的复杂项目，现在两通 30 分钟的电话就完成。

**两种截然不同的用户体验**
开发者获得的是「增强型工作流」（执行更快），而非技术用户获得的是「天哪，我变成开发者了」式的工作流（此前完全不可能的新能力）。

**改善设计与工程的协作**
沟通更好、问题解决更快，因为设计师事先就理解了系统的约束与可能性。

**产品设计团队的头号建议**

**让工程师帮忙做正确的初始配置**
让工程同事协助完成仓库初始配置与权限设置——对非开发者来说技术上手有难度，但一旦配好，它对日常工作流是变革性的。

**用自定义记忆文件引导 Claude 的行为**
写明确指令告诉 Claude：你是一位几乎没有编码经验的设计师，需要详细解释与更小、更渐进的改动。这能大幅提升 Claude 回答的质量，也让整个过程不那么令人生畏。

**用图片粘贴做原型**
用 Command+V 把截图直接粘进 Claude Code——它很擅长读懂设计稿并生成可运行的代码，是把静态设计稿变成工程师能立刻理解并在此基础上构建的交互原型时不可多得的利器。

## 面向强化学习工程的 Claude Code

强化学习工程团队专注于强化学习中的高效采样以及跨集群的权重传输。他们主要用 Claude Code 编写中小型功能、调试以及理解复杂代码库，采用一种包含频繁打检查点与回滚的迭代方式。

**Claude Code 的主要用例**

**带监督自主性的功能开发**
对于中小型功能，团队让 Claude Code 写大部分代码，同时提供监督，例如为权重传输组件实现认证机制。他们以交互方式协作，让 Claude 主导，但在跑偏时给它纠偏。

**生成测试与代码评审**
在自己实现完改动之后，他们让 Claude Code 补充测试或评审代码。这套自动化测试工作流在例常但重要的质量保障任务上省下大量时间。

**调试与错误调查**
他们用 Claude Code 调试错误，效果有好有坏——有时它能立刻定位问题并补上相关测试，有时它怎么也搞不懂问题所在，但总体而言能work时就有价值。

**理解代码库与调用栈分析**
他们工作流中最大的变化之一，是用 Claude Code 快速获取相关组件与调用栈的摘要，取代了人工读代码或生成大量调试输出。

**Kubernetes 操作指引**
他们经常问 Claude Code 那些否则需要大量谷歌搜索的 Kubernetes 操作问题，能立刻得到配置与部署方面的答案。
