*我们内部 Asana 工具在留出测试集上的表现*

**分析结果**

智能体是你发现问题的得力伙伴，它们能就各种事情给出反馈——从自相矛盾的工具描述，到低效的工具实现，再到令人困惑的工具 schema。但要记住：**智能体在反馈与响应中省略的东西，往往比它们写出来的更重要。** LLM 并不总是[言为心声](https://www.anthropic.com/research/tracing-thoughts-language-model)。

留意智能体在哪里卡住或困惑。通读评估智能体的推理与反馈（或 CoT），找出粗糙之处。检查原始记录（包括工具调用与工具响应），捕捉智能体 CoT 中未明确描述的任何行为。要读出字里行间的意思；记住你的评估智能体并不一定知道正确答案与策略。

分析你的工具调用指标。大量冗余的工具调用可能意味着分页或 Token 上限参数需要调到合适大小；针对非法参数的大量工具错误，可能意味着工具需要更清晰的描述或更好的示例。我们发布 Claude 的[网页搜索工具](https://www.anthropic.com/news/web-search)时发现，Claude 会毫无必要地往工具的 `query` 参数后面追加 `2025`，这使搜索结果产生偏置并拉低了表现（我们通过改进工具描述把 Claude 引回了正轨）。
