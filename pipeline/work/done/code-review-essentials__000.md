代码评审是任何协作式软件项目中不可或缺的一环。大型软件系统通常由不止一个人编写，因此一个高效运转的软件团队需要一套健壮的流程，让成员与代码库本身都朝正确的方向前进。

代码评审是一件强大的工具，它能够：

1. 帮助团队成员在系统变化时同步更新对系统的心智模型
2. 确保改动确实解决了问题
3. 就设计的优劣展开讨论
4. 在 bug 进入生产环境之前抓住它们
5. 保持代码风格与组织结构的一致性

把这些收益理解成一个**需求层次**会很有帮助。

![代码评审：需求层次](/images/code_review_hierarchy.png)

## 让团队成员保持在同一条线上

代码评审最关键的作用，是让团队每一位成员都朝正确的方向前进。你无法安全地修改一个自己并不理解的系统，因此代码评审让团队在认知上保持一致。当 Bob 为账务子系统提交一个拉取请求时，Amy 在评审 Bob 代码的过程中，也同步更新了自己对该系统的心智模型。Amy 有机会对不理解的部分提问，Bob 则从澄清自己的设计决策、并把工作讲给别人听中获益。一个月后当 Amy 需要修改账务子系统时，她对系统的心智模型已经是最新的、随时可用。她花更少时间读代码、在脑子里拼凑系统全貌，而把更多时间用于思考更高层的抽象与设计。每个人都赢了，因为每个人都同步在一起。
