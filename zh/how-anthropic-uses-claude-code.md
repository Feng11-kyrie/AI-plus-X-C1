## 面向数据基础设施的 Claude Code

数据基础设施团队负责为全公司各团队组织所有业务数据。他们用 Claude Code 自动化例行的数据工程任务、排查复杂的基础设施问题，并创建有文档记录的工作流，让技术与非技术团队成员都能独立访问和操作数据。

**Claude Code 的主要用例**

**用截图排查 Kubernetes 问题**
当 Kubernetes 集群宕机、无法调度新 Pod 时，该团队用 Claude Code 诊断问题。他们把仪表盘截图喂给 Claude Code，由它带着他们逐个菜单走完 Google Cloud 的界面，直到发现一条提示 Pod IP 地址耗尽的警告。随后 Claude Code 给出了创建新 IP 池并将其加入集群的确切命令，从而免去了请网络专家介入的需要。

**为财务团队做纯文本工作流**
该团队教会财务团队成员编写描述其数据工作流的纯文本文件，再把文件载入 Claude Code，得到全自动的执行。没有任何编码经验的员工可以描述这样的步骤：「查询这个仪表盘、获取信息、运行这些查询、产出 Excel 输出」，而 Claude Code 会执行整个工作流，包括主动询问日期这类必需输入。

**帮助新人导航代码库**
当新的数据科学家加入团队时，会被告知用 Claude Code 来导航他们庞大的代码库。Claude Code 会读取他们的 Claude.md 文件（文档），识别与特定任务相关的文件，解释数据管线的依赖关系，并帮助新人理解哪些上游数据源喂给了各个仪表盘。这取代了传统的数据目录与可发现性工具。

**会话结束时的文档更新**
该团队会在每个任务结束时，让 Claude Code 总结刚完成的工作会话并提出改进建议。这形成了一个持续改进的闭环：Claude Code 根据实际使用情况，帮助打磨 Claude.md 文档与工作流说明，使后续迭代更有效。

**跨多个实例的并行任务管理**
处理长时间运行的数据任务时，他们会在不同仓库、针对不同项目打开多个 Claude Code 实例。每个实例都保有完整上下文，因此当他们几小时或几天后切回来时，Claude Code 清楚记得当初在做什么、停在哪里，从而实现真正意义上的并行工作流管理，且不丢失上下文。

**数据基础设施团队的头号建议**

## 面向产品开发的 Claude Code

Claude Code 团队用自己的产品来构建 Claude Code 的更新，扩展该产品的企业能力与智能体循环功能。

**Claude Code 的主要用例**

**用自动接受模式做快速原型**
工程师们用 Claude Code 做快速原型：开启「自动接受模式」（shift+tab），并搭建自主循环，让 Claude 写代码、跑测试、持续迭代。他们把自己不熟悉的抽象问题交给 Claude，让它自主工作，然后在解决方案完成约 80% 时审阅，再接手做最后的打磨。
团队强调要从干净的 git 状态出发，并定期提交检查点，这样万一 Claude 跑偏，也能轻松回退掉错误的改动。

**核心功能的同步编码**
对于涉及应用业务逻辑的更关键功能，团队会与 Claude Code 同步协作，给出带有具体实现说明的详细提示词。他们实时监控过程，以确保代码质量、风格指南合规与架构正确，同时把重复性的编码工作交给 Claude。

**构建 Vim 模式**
他们最成功的异步项目之一，是为 Claude Code 实现 Vim 键位绑定。他们让 Claude 构建整个功能（尽管这并非优先级），最终实现约有 **70%** 来自 Claude 的自主工作，只经过几轮迭代就完成了。

**生成测试与修 bug**
他们在实现功能之后，用 Claude Code 编写全面的测试，并处理拉取请求评审中发现的简单 bug。他们还利用 GitHub Actions 集成，让 Claude 自动处理拉取请求下的评论，例如格式问题或函数重命名。

**探索代码库**
面对不熟悉的代码库（例如 monorepo 或 API 侧）时，团队用 Claude Code 快速理解系统的运作方式。他们不再等 Slack 回复，而是直接向 Claude 要解释与代码位置，省下大量切换上下文的时间。

## 面向安全工程的 Claude Code

安全工程团队专注于保障软件开发生命周期的安全、供应链安全与开发环境安全。他们大量使用 Claude Code 来编写和调试代码。

**Claude Code 的主要用例**

**复杂基础设施调试**
处理故障事件时，他们把调用栈与文档喂给 Claude Code，让它沿代码库追踪控制流。这显著缩短了生产问题的解决时间——原本需要 10–15 分钟人工扫代码才能理解的问题，现在大约 5 分钟就能搞定。

**Terraform 代码评审与分析**
对于需要安全审批的基础设施变更，他们把 Terraform plan 复制进 Claude Code，问「这会产生什么效果？我会不会后悔？」这形成了更紧的反馈回路，让安全团队能更快评审并批准基础设施变更，减少开发流程中的阻塞。

**文档整合与运维手册**
他们让 Claude Code 摄取多个文档来源，产出 markdown 格式的运维手册、排障指南与总览。他们把这些浓缩后的文档作为调试真实问题的上下文，比在完整知识库里翻找更高效。

**测试驱动开发工作流**
他们不再沿用过去「设计文档 → 潦草代码 → 重构 → 放弃测试」的模式，而是让 Claude Code 先给出伪代码，引导它走测试驱动开发，并定期检查、在卡住时给它纠偏，从而得到更可靠、更可测的代码。

**上下文切换与项目上手**
在为既有项目（例如用于安全审批工作流的 Web 应用 dependant）做贡献时，他们会用 Claude Code 编写、评审并执行以 markdown 写在代码库中的规格说明，从而在**几天**而非**几周**内做出有意义的贡献。

## 面向推理的 Claude Code

推理团队负责管理记忆系统——在 Claude 读取你的提示词并生成响应时，用于存储信息的系统。团队成员（尤其是刚接触机器学习的人）可以大量借助 Claude Code 来弥合这一知识鸿沟、加快工作。

**Claude Code 的主要用例**

**理解代码库与上手**
加入复杂代码库时，团队高度依赖 Claude Code 来快速理解架构。他们不再手动搜索 GitHub 仓库，而是让 Claude 找出哪些文件调用了特定功能，几秒就能得到结果，而不必问同事或手工搜索。

**生成覆盖边界情况的单元测试**
写完核心功能后，他们让 Claude 编写全面的单元测试。Claude 会自动补上被遗漏的边界情况，把原本要耗费大量脑力的工作压缩到几分钟完成，相当于一位可随时审阅的编码助手。

**解释机器学习概念**
由于没有机器学习背景，团队成员依赖 Claude 来解释模型特有的函数与设置。原本需要一小时谷歌搜索与读文档的事，现在 10–20 分钟就能完成，研究时间减少 **80%**。

**跨语言代码翻译**
在不同编程语言中测试功能时，他们说明想测什么，Claude 就用所需语言（例如 Rust）写出逻辑，从而不必为测试专门去学一门新语言。

**命令回忆与 Kubernetes 管理**
不必再记复杂的 Kubernetes 命令，他们直接问 Claude 正确语法，比如「怎么获取所有 Pod 或部署状态」，就能得到基础设施工作所需的确切命令。

## 面向数据科学与可视化的 Claude Code

数据科学与机器学习工程团队需要精密的可视化工具来理解模型表现，但构建这类工具往往需要掌握不熟悉的语言与框架。Claude Code 让这些团队无需变成全栈开发者，就能构建生产级的数据分析仪表盘。

**Claude Code 的主要用例**

**构建 JavaScript／TypeScript 仪表盘应用**
尽管「对 JavaScript 和 TypeScript 知之甚少」，该团队仍用 Claude Code 构建完整的 React 应用，用于可视化强化学习模型的表现与训练数据。他们把控制权交给 Claude，让它从零写出完整应用——例如一个 5,000 行的 TypeScript 应用——而自己无需理解这些代码。这一点很关键，因为可视化应用相对独立、不需要理解整个 monorepo，从而能快速做出工具原型，用于理解训练与评估期间模型的表现。

**处理重复性重构任务**
面对合并冲突、或复杂到超出编辑器宏能力、又没大到值得专门开发投入的半复杂文件重构时，他们把 Claude Code 当成「老虎机」用——提交当前状态，让 Claude 自主工作 30 分钟，然后要么接受方案，要么在失败时推倒重来。

**创建持久化的分析工具，而不是一次性 notebook**
团队不再构建用完即弃的 Jupyter notebook，而是让 Claude 构建可长期复用、能跨未来模型评估使用的 React 仪表盘。这很重要，因为理解 Claude 的表现「是团队最重要的事情之一」——他们需要理解模型在训练与评估期间的表现，而「这实际上并不简单，光看一个数字往上走，简单工具拿不到多少信号」。

**零依赖的任务委派**
对于完全陌生的代码库或语言中的任务，他们把整个实现委派给 Claude Code，利用它从 monorepo 中收集上下文并执行任务的能力，自己不必参与实际编码过程。这让他们能在专长之外的领域也保持产出，而不必花时间去学新技术。

## 面向 API 的 Claude Code

API 知识团队负责 PDF 支持、引用与网页搜索这类功能，把额外的知识带进 Claude 的上下文窗口。在庞大复杂的代码库中工作，意味着不断遇到不熟悉的代码段、要花大量时间弄清某个任务该看哪些文件，并在动手改动前先构建上下文。Claude Code 改善了这种体验：它像一位向导，帮助他们理解系统架构、定位相关文件、解释复杂的交互。

**Claude Code 的主要用例**

**第一步的工作流规划**
团队把 Claude Code 当作任何任务的「第一站」，让它指出修 bug、做功能或做分析该看哪些文件。这取代了传统的、在动工前手动浏览代码库并收集上下文的耗时流程。

**跨代码库的独立调试**
团队现在有信心去处理代码库中不熟悉部分的 bug，而不必求助他人。他们可以问 Claude：「你觉得你能修好这个 bug 吗？我观察到的行为是这样的」，往往立刻就有进展——这在过去因为所需的时间投入而不可行。

**通过自产自用来做模型迭代测试**
